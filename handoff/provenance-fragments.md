## What the branch does
* spec/abi/PROVENANCE is split into 20 fragments, spec/abi/provenance.d/<ID>.txt (front matter `order: 10..200`,
  text unchanged). The view is generated by `cargo xtask records-gen` (xtask/src/provenance.rs): current counts of
  17 tables (rows plus distinct columns), then the fragments in order. It is not listed in records/views.toml, so
  merge_next treats it as an ordinary `@generated` file (a conflict takes next's copy). Off the train the static check
  `records-gen` reports a stale view as advisory, and on the train (which regenerates in place) as fatal, as for the
  decision views (D-X.55/59). A malformed fragment is an error everywhere. Header stories add a fragment and do
  not touch the view (spec/abi/provenance.d/README.md).
* `cargo xtask records-gen --check <view>...` checks only the named views.
* abi_extract.py writes its own fragment (`--story`). appendix_c.py reads the ldd line from the fragments.
  CONTRIBUTING.md points to the README.
* validation/headers_unshipped.tsv is NOT generated: its `waits_for` column holds hand-written reasons, and the list
  is a ratchet (P4 fails when a header stops shipping). A generated list would absorb that failure.
