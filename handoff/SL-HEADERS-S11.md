* **P1 fixed (hex floats).** `headers-gen` `literal()` now writes every `macros.tsv` floating constant as a decimal literal that
  reads back as the same value (exact bignum conversion `hex_float_to_decimal`; 9, 17, 21, 36 significant digits for

* **fenv.h:** the compiler has a built-in `int fegetexceptflag (void *, int)` (and `fesetexceptflag`); the exact ABI prototype
  with `fexcept_t *` differs from it, which `-Wsystem-headers -Werror` rejects. The template wraps the declarations in a
  `#pragma GCC diagnostic push/ignored "-Wbuiltin-declaration-mismatch"/pop`.
* **iscanonical (ruling #6395), triaged. No difference from the reference, no compat flag.** Black-box probe of the
  reference (probe in `~/work/SL-HEADERS-S11-2/probe/pd.c` on the build host, long double bit patterns of the probe's own):
  `iscanonical` is 1 for 1.0, a denormal, +inf, a quiet NaN and 0 for the pseudo-denormal (exp 0, integer bit 1), an
  unnormal, a pseudo-infinity and a pseudo-NaN. Spec: s10.1 contract "whether ... a value is canonical", and s10.2
  `canonicalize` "It matters only for formats with non-canonical encodings (x87 pseudo-denormals) ... An encoding that
  represents no value (x87 unnormals, pseudo-infinities, pseudo-NaNs) ...": the spec names the pseudo-denormal as the
  non-canonical encoding. GCC's manual lists no `iscanonical` builtin (the compiler's own diagnostic for
  `__builtin_iscanonical` is an implicit declaration), so the header calls the library's `__iscanonicall`
  (`math::classify::is_canonical`: false for pseudo-denormals and invalid encodings, already in the library) for the x87
  types and is 1 for the other types. The run-1 template's constant `1` was wrong and is replaced: `__iscanonical(x)`
  macro and `iscanonical(x) = __iscanonical(x)`. The three agree, so nothing needs a ruling. The C standard text itself was not
  available on the build hosts (no copy offline); I did not quote it.
* **tgmath.h written** (generated by a scratch script from the declared functions of math.h and complex.h, 116 macros,
  `@@owns-macro`; the script is not in the tree: the template is the artefact). A family with one candidate function
