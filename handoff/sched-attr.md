# SCHED-ATTR: sched_getattr / sched_setattr at GLIBC_2.41 (owner ruling R3)

**State (2026-11-14):** branch `task/sched-attr` from origin/next 2d5625a3e; code, spec, tests, plants and the
pending decision record are done. **Held by START-UP LAYOUT JITTER (#4347):** `cargo xtask so` breaks the
STARTUP-DATA-WINDOWS contract by one page (numbers below). The change touches no start-up code, so the rule says
do not chase it; the story waits for the layout fix (LAYOUT-RETHINK LT-1/LT-4).

## What was done

* `crates/boundary/src/posix/s24_system.rs`: `sched_setattr(pid, attr, flags)` and
  `sched_getattr(pid, attr, size, flags)`, thin wrappers through `raw::syscall` (the `capget` pattern): the
  caller's `struct sched_attr` goes to the kernel unchanged. A typed copy (the `mount_setattr`/`MountAttr` route)
  was rejected: the kernel writes its own size back on E2BIG, and a copy would lose that and refuse sizes newer
  kernels accept. No `unsafe`.
* Spec: clause `s24_3_c_6` (§24.3), the §24.3 heading and Kernel line, Appendix B entries `@2.41` with a
  preamble note, Appendix C.0 "Additions" row, C.1 row counts, C.2 libc node list (GLIBC_2.41 (R3)), totals.
  `spec/abi/versions.tsv` and `versions-aarch64.tsv`: two `GLIBC_2.41 default FUNC GLOBAL` rows each;
  `prototypes.tsv`: two rows. `spec/clauses.tsv`, `spec/symbols.tsv` regenerated by `cargo xtask stubs`.
* Decision record `records/pending/SCHED-ATTR-1.toml` (D-NEW, series D-24): CI assigns the id.
* Tests: `sym_sched_getattr`, `sym_sched_setattr` (crates/boundary/tests/s24_system_symbols.rs: size protocol,
  E2BIG write-back, EINVAL/ESRCH/EFAULT/EPERM, errno kept on success, SCHED_OTHER nice 5 and SCHED_IDLE read
  back, each mutation in its own thread); `s24_3_c_6` (crates/core/tests/s24_system_clauses.rs: pid 0 is the
  calling thread, a TID names that thread).
* Plants `handoff/sched-attr.plants`: 5 of 5 CAUGHT (wrong syscall number, dropped flags, hidden errors,
  swapped size/flags, ignored pid), no WARN lines.
