## Premises that look false

1. **"A measured impact entry is a gain" (ops/tripwire.py, `is_gain` and `best_gain`; GOALS E4).** Plants are
   required for every code story, so nearly every run records a `coverage` entry "0 -> N plants". Over all chains in
   the store: 290 chains have gains; the headline (`best_gain`, largest relative change) is `coverage` for 225 of them,
   because a before of 0 ranks as an infinite change (406 of 1214 gain entries have before = 0). 122 chains have only
   coverage / tooling / unblock entries. 80 chains with a real perf / faults / size gain show a coverage headline
   instead. The 11-23 digest's frame check shows "gain: yes (coverage: plants ...)" for all three top chains,
   including LD-RELR-LOOP (whose real figure is -30.2k instructions per start) and INTERNAL-ALLOC-ROUTING (whose run 2
   measured a cost). Direction is not checked either: TB-FOREIGN-WORDS-LOW's "errno_location per call 9 -> 11" counts
   as a perf gain. Consequence: the continuation and agent-hour triggers are excused by a by-product of the process,
   so the tripwire in practice fires only on reds; all six tripwire reviews in the window concluded "not a rabbit hole,
   integration friction". Owed #32 (direction of impact entries) has been due since 11-20T02:42.
2. **"The token governor paces dispatch" (A_MAX-GOVERNOR, 11-08).** `settings` holds no `gov_*` key, so
   `gov_week_usd` is its default "0" ("no plan (off)"). On 11-22T20:41Z the owner paused new jobs by hand at 97% of
   the weekly usage. The owner was the early warning (E8) for something a built capability is meant to do.
3. **"Train 929/932 reds are a merge interaction" (LOG 11-22T22:17Z).** Corrected by the coordinator at 00:41Z
   (#7740), but LD-RELR-LOOP-3 had already run on it (merge only, "cause not found"). Noted for E6: the premise was
   found false at hand-back, one run late.

## Processes due for a rethink

1. **Tripwire gain test (E4).** Count as gain only kinds that serve a goal (perf, faults, size, accuracy,
   correctness, an unblock that landed), in the improving direction; never coverage or tooling; rank headlines by
   kind first. Without this the E4 indicator watches reds only.
2. **Owner rulings on small net-positive trades (E8).** #7759 asks the owner about +1 instruction once per process
   against -16 per allocation; #7708 ("close call per owner") was the same shape. Under ALWAYS FORWARD every such
   trade becomes an owner decision. A standing delegation would remove them (ruling below).
3. **Start-up bounds as constants in a test source.** `hot_text_products.rs` keeps its bounds as Rust constants
   (`TRUE_BOUND`, `LOCALE_BOUND`, `TOOL_BOUND`, ...) that most start-up stories tighten; 3 of 18 CI conflicts in the
   window were in that file, and one cost LD-RELR-LOOP a whole continuation (-4). One row per line in a data file (or
   a CI merge rule "take the smaller bound, then re-run") would make independent tightenings merge cleanly. `so.rs`
   (3) and `ld/dlopen.rs` (3) are the other repeat conflict files.
4. **Owed backlog (E5).** 154 owed items opened in the window, 81 paid; 75 open, 72 past due, 37 of them since 11-20.
   Among them #132 (routing of private hand-back sections, marked urgent, due 11-22T03:08) and #32 above. The owed
   list grows by ~24 a day; it has become a second backlog that only the coordinator drains. Pay #132 and #32 first;
   turn ops-tool owes into ordinary stories (pipeline/tooling stories landed at 2.57 agent-h each in the window).
5. **CI red attribution.** 8 of the 20 red trains carry attribution basis "none" (nobody blamed); each needs a person
   to triage. Not costed further here.
6. **Snapshot cadence (minor).** A snapshot per Yohane fix (~5 a day) is a second whole-system gate; batching to
   about two a day, plus one on demand for an urgent Yohane issue, would save roughly half of 23 agent-h per 72 h. Its
   regression catches argue for keeping the checks, not the count; the owner's P4 indicator is "on demand".

## Recommendation

Continue as is in content (loader / start-up first, heap for Yohane #21, headers). Make these named changes:
the tripwire gain test (coordinator, owed #32), the governor's weekly plan (owner number), a delegation rule for small
net-positive trades (owner), bounds as data for `hot_text_products.rs` (a small tooling story), and pay #132 before
other owes. No RETHINK story and no stop.
